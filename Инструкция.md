# Крополятор — как пользоваться

Инструмент для бэша в планиметрии. Вы чертите в GeoGebra мышью, а справа сама
собой набирается таблица «объект → его точная координата».

Движка два, и переключаются они кнопкой в левом верхнем углу:

- **Компланатор** — комплексные числа, описанная окружность единичная;
- **Бариканатор** — барицентрика относительно `ABC`.

Первые две трети этого файла — про Компланатор; про второй движок отдельная
глава в конце, и начинать её стоит с раздела «Чем он отличается»: он подскажет,
какой движок брать под вашу задачу. Про то, как оно устроено внутри, написано в
`README.md`.


## В двух словах

Первые три свободные точки, которые вы поставите, объявляются вершинами
треугольника `A, B, C`. Их **описанная окружность считается единичной с центром
в нуле**, то есть вершины получают буквы `a, b, c` с правилом `ā = 1/a`. Дальше
любое построение пересчитывается через эти буквы точно, в целых дробях, без
всякой численности.

То, что на экране `A, B, C` лежат совсем не на единичной окружности, движку не
мешает: он работает в нормированных координатах `z ↦ (z − O)/R`, а это подобие,
под которым все построения сохраняются.


## Запуск

Двойной клик по **«Запустить Крополятор.bat»** — поднимется локальный сервер и
откроется браузер. Окно консоли не закрывайте, пока работаете.

Либо вручную:

```
python -m http.server 5173
```

и открыть `http://localhost:5173/public/index.html`.

Первая загрузка занимает около минуты: апплет GeoGebra качается с их серверов.
Ждите, пока в правом верхнем углу панели не появится **«готов»** — до этого
командная строка честно скажет «апплет ещё не загрузился».

Есть ещё `Крополятор.html` — приложение одним файлом. Его можно просто
отправить кому-то: открывается двойным кликом, ничего ставить не надо. Внутри
**только Компланатор**: Бариканатор, генератор теорем и выгрузка задачи
работают на сайте, где есть у кого спросить про доступ, а файл без сети этого
сделать не может. Пересобирается командой `npm run build` после правок
исходников.


## Первое построение

1. Поставьте три точки — они станут `A, B, C` (в таблице будут помечены точкой •).
2. Стройте что угодно обычными инструментами GeoGebra.
3. Каждый объект, который движок понял, тут же появляется в таблице справа.

Ширину панели можно тянуть за разделитель, двойной клик по нему возвращает треть
экрана.


## Как читать панель

| в строке | что значит |
|---|---|
| `A • a` | свободная точка-вершина, её буква |
| `H  a + b + c` | построенная точка и её координата |
| `a  z + b c z̄ = b + c` | прямая, уравнением |
| `k  z z̄ = 1` | окружность, уравнением |
| курсивом красным | движок эту команду не понял; наведите мышь — во всплывающей подсказке будет то, что он пытался разобрать |
| **красная приписка** | символьный ответ разошёлся с настоящим положением точки на чертеже |

Красная приписка — это **живая сверка**: движок подставляет в свой ответ
настоящие координаты чертежа и сравнивает с тем, где точка на самом деле.
Если она появилась, ответу верить нельзя (кроме одного известного случая, см.
раздел «Чего не умеет»).

**Кнопка «кан.»** рядом с каждым уравнением переключает запись:

| | как обычно | по кнопке |
|---|---|---|
| прямая | `z + β·z̄ = δ` | `A·z + B·z̄ + C = 0` |
| окружность | `(z − o)(z̄ − ō) = r²` | `z z̄ + A·z + Ā·z̄ + C = 0` |

Обычная запись нормирована (коэффициент при `z` равен единице) — она
единственна, и по ней движок сравнивает прямые. Каноническая — привычная
бумажная, со снятыми знаменателями.

Точки сверх трёх тоже можно. Четвёртая свободная точка получает букву `d` и
**независимую** `d̄` — под строкой будет подписано «d̄ — независима». А точка,
посаженная на прямую или окружность инструментом «Точка на объекте», получает
своё правило сопряжения, и оно тоже подписано: именно поэтому в ответах не
всплывают лишние буквы.


## Что понимает из построений мышью

| строите | понимает |
|---|---|
| точку, прямую, отрезок, луч | да |
| середину отрезка | `Midpoint` |
| перпендикуляр, параллельную | да |
| серединный перпендикуляр | да |
| пересечение | прямых — всегда; с окружностью — см. ниже |
| окружность | по трём точкам, по центру и точке |
| центр окружности | `Center` |
| касательную, поляру | касательную — в точке НА окружности |
| проекцию точки на прямую | `ClosestPoint` |
| отражение от точки и от прямой | да |
| инверсию | отражение точки в окружности |
| гомотетию | коэффициент обязан быть точной дробью |
| поворот | только на углы, кратные 90° |
| центроид треугольника | да |
| `TriangleCenter(A,B,C,n)` | X(2), X(3), X(4), X(5) |

**Гомотетия и поворот требуют явно указанного центра.** Без него GeoGebra берёт
своё начало координат, а у движка ноль — это центр описанной окружности; точки
разные, и молча подставить ноль значило бы соврать.

**Ортоцентра как инструмента в GeoGebra нет.** Стройте руками (два
перпендикуляра и пересечение) или командой `TriangleCenter(A,B,C,4)`. Мелочь:
первый вызов `TriangleCenter` после загрузки апплета падает — GeoGebra
подгружает эту команду лениво; просто повторите.

**Пересечение с окружностью** движок берёт, когда обходится без радикалов:
когда один из корней — уже построенная точка (тогда второй по Виету), когда
это касание, или когда уравнение на деле линейное. Иначе честно скажет, что
нужны радикалы.


## Командная строка: условия

Блок «командная строка — по системе на строку». **Каждая строка — отдельная
система.** Запуск — кнопкой или Ctrl+Enter.

Идея: достроить подобный треугольник мышью — это десяток вспомогательных
объектов. Условие `similar(A,B,C,B,C,X)` описывает ту же точку одной строкой.
Имя, которого на чертеже ещё нет (`X`), — это неизвестная. Найденная точка
становится **обычной зависимой точкой GeoGebra**: её видно, её можно выделять,
брать в дальнейшие построения, она едет за вершинами и переживает сохранение.

### Сколько условий нужно

Одна неизвестная точка — это **две** вещественные степени свободы. Условия
бывают двух весов:

| вес | команды |
|---|---|
| **2** — фиксирует точку целиком | `similar`, `vectors`, `harm`, `krokhalyator` |
| **1** — оставляет точку на прямой | `angle`, `anglesum`, `paral`, `perpen`, `collinear` |
| особый — окружность | `cocycl` |

Поэтому `collinear(A,B,X)` в одиночку даст «условий не хватает: решений
бесконечно много», а вот пара условий по одному весу работает:

```
collinear(A,B,X) perpen(C,X,A,B)        →   X = -(a b - a c - b c - c²)/(2c)
```

Это проекция `C` на `AB`. Два условия в одной строке разделяются пробелом или
точкой с запятой.

### Список команд

| команда | смысл |
|---|---|
| `similar(X1..X6)` | треугольник X1X2X3 подобен X4X5X6, ориентация та же |
| `angle(X1..X6)` | направленный угол X1X2X3 равен направленному X4X5X6 |
| `anglesum(+,X1,X2,X3, -,X4,X5,X6, …)` | знакопеременная сумма направленных углов равна нулю |
| `vectors(X1,X2,X3,X4)` | вектор X1X2 равен вектору X3X4 |
| `cocycl(X1..X4)` | четыре точки на одной окружности |
| `paral(X1..X4)` | X1X2 ∥ X3X4 |
| `perpen(X1..X4)` | X1X2 ⟂ X3X4 |
| `harm(X1..X4)` | [X1X2, X3X4] = −1 |
| `collinear(X1,X2,X3)` | три точки на одной прямой |
| `krokhalyator(X1..X4)` | четвёрка ортоцентрическая |

Углы всюду **направленные, по модулю 180°** — то есть так, как их и считают в
бэше: без разбора случаев на конфигурацию.

`anglesum` берёт аргументы четвёрками «знак, три точки». Знак — отдельным
аргументом, `+` или `−`. Из двух слагаемых получается ровно `angle`:

```
anglesum(+,A,B,C, -,A,U,C) collinear(M,U,A)
```

`krokhalyator` даёт сразу два условия, поэтому одной команды хватает:

```
krokhalyator(A,B,C,T)                   →   T = a + b + c
```

то есть ортоцентр — ровно то, что и должно быть.

### Аргумент — это выражение

Аргументом может быть не только имя точки, а **любое выражение**:

```
similar(A,B,C, (A+B)/2, (B+C)/2, R)
vectors(A, B, (A+C)/2, Z)
collinear(A,B,R) perpen((A+B)/2, R, A, B)
perpen(A, P, Q + A/3, (P**2 - X**2)/(P + X + Q))
```

Работают `+ − * /`, скобки, целые степени (`^` или `**`, как в Python) и
`conj(...)`. Неизвестная может стоять и внутри выражения — `collinear(A, B,
(A+X)/2)` вполне себе линейное условие.

Это и было главным неудобством раньше: под каждую середину и каждую вершину
педального треугольника приходилось заводить отдельную точку чертежа, хотя в
условие она входит один раз.

### Что скажет, если что-то не так

| сообщение | что делать |
|---|---|
| «условий не хватает: осталось N степеней свободы» | добавить условий по весам из таблицы выше |
| «условия противоречат друг другу» | система несовместна |
| «в строке нет ни одной новой точки» | все имена уже есть на чертеже, решать нечего |
| «нужны радикалы» | пересечение не выражается через `a, b, c` рационально |
| «все решения совпадают с уже построенными точками» | условие выполняется старой точкой; уточните его |
| «решение не согласовано с сопряжением» | условия описывают то, чего на плоскости не бывает |


## Командная строка: построения

Иногда формула уже известна и нужно просто поставить точку. Такие команды
условий не накладывают, поэтому **в одной строке с условиями не смешиваются** —
об этом будет сказано прямо.

| команда | что делает |
|---|---|
| `buildpoint(выражение)` | ставит точку по формуле |
| `buildline(A, B, C)` | прямая по уравнению `A·z + B·z̄ + C = 0` |
| `radline(объект, объект)` | радикальная ось |

Построению можно дать имя, и тогда на него можно ссылаться дальше:

```
buildpoint(G = (A+B+C)/3)              →   центроид
buildpoint((P+D+X)/3)                  →   имя выдаст само: K1, K2, …
buildline(m = 1, A*B, -(A+B))          →   z + ab·z̄ = a + b, то есть хорда AB
radline(p = A, B)                      →   срединный перпендикуляр к AB
radline(t = k, A)                      →   z + a²·z̄ = 2a, касательная в A
```

Точка = окружность нулевого радиуса, поэтому у `radline` частные случаи выходят
даром: ось двух точек — срединный перпендикуляр, а точки и проходящей через неё
окружности — касательная. Окружность указывается **буквой с панели**, точка —
любым выражением.

Повторный запуск той же строки **обновляет** построенное, а не плодит копии.

### Про степень выражения и точку 1

`buildpoint` не требует, чтобы выражение было первой степени: `A^2` и `1/A` —
законные точки описанной окружности.

Смысл им придаёт то, что нормировка чертежа **не содержит поворота**: комплексная
единица — вполне определённая точка описанной окружности (на луче из центра
вправо, вдоль оси абсцисс GeoGebra). Если вы работаете с `a²`, `1/a` и прочим,
где суммарная степень не равна единице, полезно поставить её на чертёж и видеть,
относительно чего всё считается:

```
buildpoint(1)
```

Специально её никто не заводит и нигде не показывает — она появляется ровно
тогда, когда её попросили построить.

### Почему `buildline` может отказаться

У настоящей прямой на плоскости `|B/A| = 1` и свободный член согласован с
сопряжением. Если нет — уравнение и сопряжённое ему задают разные прямые, то
есть ни одной, и движок скажет об этом вместо того, чтобы нарисовать чепуху:

```
buildline(1, 2, 0)     →   |B/A| ≠ 1 — такое уравнение не задаёт прямую
```


## Строка выражений

Блок «выражения от координат — по выражению на строку». Считает что угодно от
координат построенных точек. Запуск — кнопкой или Ctrl+Enter.

```
H - A                              →   b + c
ratio = (H-A)/(H-B)                →   (b + c)/(a + c)
ratio - conj(ratio)                →   -(a - b)(b + c)/(b(a + c))
```

Операции: `+ − * /`, скобки, целые степени (`^` или `**`), `conj(...)`.
Умножение пишется **явно**: `2*A`, не `2A`. Имя переменной должно быть не короче
двух знаков, иначе его не отличить от точки чертежа.

Ответ раскладывается на множители; если он оказался нулём — так и подписано.

### Проверки пишутся явно

Автоматически на вещественность движок не проверяет: это стоит втрое дороже
самого вычисления, а нужно далеко не всегда. Зато ноль виден сразу и бесплатно.

| проверить | написать |
|---|---|
| X, Y, Z на одной прямой | `r = (X-Y)/(X-Z)`, затем `r - conj(r)` |
| XY ⟂ ZW | `q = (X-Y)/(Z-W)`, затем `q + conj(q)` |
| X на описанной | `X*conj(X) - 1` |
| XY = ZW | `distance(X,Y) - distance(Z,W)` |
| тождество | само выражение |

### distance

`distance(объект, объект)` — **квадрат** расстояния. Именно квадрат: сам корень
иррационален и вывел бы выражение за пределы поля, в котором работает движок, а
во всех проверках длина и так стоит в квадрате.

Точка задаётся выражением, прямая и окружность — своей буквой с панели:

```
distance(A, B)                     →   -(a - b)²/(a b)
distance(A, a)                     →   (a - b)²(a - c)²/(4a² b c)     квадрат высоты из A
distance(A, k)                     →   0                              A на описанной
distance((P-2*A)*B/C, f)           →   до прямой f
```

До прямой считается честное расстояние. До окружности — **степень точки**, то
есть точка просто подставляется в уравнение; расстояние до самой окружности
потребовало бы корня.

Минус перед дробью не должен смущать: `-(a-b)²/(ab)` вещественно и
положительно — на единичной окружности `(a−b)²/(ab)` отрицательно.


## Режим «движок выключен»

Кнопка **«движок включён / выключен»** в шапке. Пока он выключен, стройте что
угодно — в таблицу это не попадёт и буквы не получит.

Важно: построенное при выключенном движке остаётся невидимым для него **и после
включения обратно**. Иначе объект вдруг получил бы образующую, а построенные
раньше его дети — уже нет. Если потом построить что-то, опирающееся на такой
объект, движок скажет прямо: «построен при выключенном Компланаторе».

Годится для вспомогательной обвязки, подписей, стрелочек — всего, что движку
осмысливать незачем.


## Чего не умеет и почему

**Радикалов нет и не планируется.** Всё, что требует извлечь корень из
дискриминанта, движок не решает. Отсюда: касательные из внешней точки (точки
касания иррациональны), пересечение двух «чужих» окружностей без общей
построенной точки, инверсия окружности в окружность.

**Инцентр X(1)** и вообще центры треугольника, зависящие от длин сторон, — не
рациональные функции от `a, b, c`. `TriangleCenter` поддержан для X(2), X(3),
X(4), X(5).

**`ClosestPoint` на отрезке.** GeoGebra прижимает результат к концу отрезка, а
движок считает проекцию на всю прямую. У тупоугольного треугольника основание
высоты выходит за сторону — и живая сверка покажет расхождение. Символьный ответ
при этом **верен**: расходятся не он с истиной, а две разные точки. Если хотите
без красноты — стройте перпендикуляр к прямой, а не проекцию на отрезок.

**Букв на всех не хватит:** свободных точек сверх трёх можно завести
семнадцать.

**Удаление вершины пересобирает построение целиком**, и буквы при этом могут
перераспределиться.

**Полной факторизации нет.** Многочлен степени ≥ 2 по каждой переменной, без
квадратов и без линейных множителей, печатается неразложенным. В планиметрии
такое встречается редко.


## Шпаргалка

```
# условия (система на строку, Ctrl+Enter)
collinear(A,B,X) perpen(C,X,A,B)         проекция C на AB
similar(A,B,C,B,C,X)                     достроить подобный
krokhalyator(A,B,C,X)                    четвёртая точка ортоцентрической четвёрки
cocycl(A,B,C,X) collinear(A,M,X)         вторая точка пересечения чевианы с описанной
anglesum(+,A,B,C, -,A,X,C) …             равенство/сумма направленных углов
perpen(A, P, (Q+A)/3, X)                 аргумент — любое выражение

# построения (нельзя мешать с условиями)
buildpoint(G = (A+B+C)/3)                точка по формуле
buildpoint(1)                            показать комплексную единицу
buildline(m = 1, A*B, -(A+B))            прямая по уравнению
radline(t = k, A)                        радикальная ось / касательная
homothety(k, n)                          оба центра гомотетии двух окружностей
tangent(P, k)                            касательные из точки к окружности

# условие на точки (по системе на строку)
perpen(A, M, B, C)                       когда медиана ⟂ основанию
collinear(A, M, H)                       когда медиана проходит через ортоцентр

# выражения (по выражению на строку)
r = (X-Y)/(X-Z)   →   r - conj(r)        ноль ⟺ X, Y, Z коллинеарны
q = (X-Y)/(Z-W)   →   q + conj(q)        ноль ⟺ XY ⟂ ZW
X*conj(X) - 1                            ноль ⟺ X на описанной
distance(X,Y) - distance(Z,W)            ноль ⟺ XY = ZW
```

## Условие на точки

Командная строка отвечает на вопрос «где стоит точка». Эта — на обратный:
**при каких вершинах написанное вообще выполняется**.

Пишете условие на уже построенные точки — неизвестных тут нет, — и получаете
уравнение на сам треугольник. Команды те же самые.

```
perpen(A, M, B, C)      где M — середина BC
```

Ответ:

```
(b − c)(a² − bc) = 0
```

Читается так: либо `b = c` (вершины совпали, вырождение), либо `a² = bc`. Второе
и есть содержательный случай: для точек единичной окружности `a² = bc`
равносильно `AB = AC`, то есть треугольник равнобедренный.

Именно поэтому ответ раскладывается на множители: **каждый множитель — отдельный
случай**, при котором условие выполняется. Смотреть надо на них, а не на
уравнение целиком.

Если условие верно для любого треугольника, так и написано: «выполняется
всегда». Например `perpen(A, H, B, C)` — высота из A перпендикулярна BC по
определению, никакого условия на вершины тут нет.

Точки должны быть построены заранее: на непостроенное имя движок ругается, а не
объявляет его неизвестным — для неизвестных есть командная строка.

## Центры гомотетии

```
homothety(k, n)
```

Строит **оба** центра гомотетии двух окружностей — внешний и внутренний.
Окружности задаются буквами с панели.

Классический пример: описанная окружность и окружность девяти точек дают ровно
**ортоцентр и центроид**. Годится как проверка, что всё работает.

Какая из двух точек внешняя, а какая внутренняя, формула не знает: это зависит
от знака квадратного корня, а он символьно не определён. Смотрите на чертёж.

Если радиусы равны, внешний центр уходит на бесконечность, и строится только
внутренний — середина между центрами.

Иногда движок откажется: центр выражается через произведение радиусов `r₁·r₂`, и
если оно иррационально, считать нечего. Но это происходит реже, чем можно
подумать: произведение бывает рациональным даже когда каждый радиус — нет.

## Касательные из точки

```
tangent(P, k)
```

`P` — любое выражение, `k` — окружность с панели.

Если `P` лежит на окружности, касательная одна — та самая в этой точке.

Если `P` снаружи, касательных две, но найти их удаётся не всегда: точки касания
— корни квадратного уравнения, и они иррациональны, если среди уже построенных
точек нужных нет. Тогда движок честно скажет, что нужны радикалы, а не выдаст
неверный ответ.

Работает наверняка, когда точки касания уже есть на чертеже. Скажем, из точки
пересечения касательных в `B` и `C` касательные найдутся сразу — они касаются
ровно в `B` и `C`.

## Если строка говорит «не посчитано»

Значит счёт этого объекта не уложился в отведённые 5 секунд. Это **не ошибка**:
ответ существует, он просто дорогой.

Рядом появится кнопка **«посчитать»** и грубая оценка — секунды, десятки секунд
или минуты. Оценка приблизительная: точную назвать нельзя, стоимость зависит не
только от размера выражения. Нажимаете — движок досчитывает без ограничения по
времени и потом пишет, сколько ушло на самом деле.

Почему не считать сразу до конца: пока идёт счёт, вкладка не отвечает. Лучше
показать честное «не посчитано» и дать решить вам — только вы знаете, нужна ли
вам эта конкретная точка настолько, чтобы ждать минуту.

Почему не посчитать «примерно, зато быстро»: сокращение дроби здесь не украшение.
Недосокращённый результат становится входом следующего построения, и рост идёт с
умножением — сэкономив секунду сейчас, вы получите зависание через два шага.

## Если тормозит сам чертёж

Бывает так: в панели написано, что счёт занял двести миллисекунд, а вкладка при
этом стоит десять секунд. Это значит, что считает **не Компланатор, а GeoGebra**.

Причина в длинных цепочках. Компланатор отдаёт GeoGebra определения через
вершины `A, B, C`, и объект, построенный поверх объекта поверх объекта,
разворачивается во всю цепочку целиком. Точка на касательной — четыре сотни
знаков, прямая через неё — уже под шесть тысяч. GeoGebra пересчитывает это на
каждое обновление чертежа, и никакие наши ограничения ей не указ: там считает
её код, а не наш.

Кнопка **«рисовать / не рисовать»** в шапке это обходит. Выключаете — движок
по-прежнему всё считает и показывает формулы в таблице, но на чертеже ничего не
строит. Для разбора задачи этого обычно достаточно, а GeoGebra остаётся быстрой.

Строка **«счёт: …»** под заголовком «Алгебра» показывает, сколько времени ушло
именно у Компланатора, и какой объект оказался самым долгим. По ней и видно, к
кому претензия.

## Когда GeoGebra виснет на пересечении

Бывает, что вы пытаетесь отметить пересечение мышью — и GeoGebra перестаёт
отвечать, точка не появляется нигде, а браузер предлагает закрыть страницу. При
этом строка «счёт» в панели показывает какие-то жалкие триста миллисекунд.

Это значит, что виснет не Компланатор, а GeoGebra, вычисляя пересечение сама.
Наш код в этот момент даже не запускался — поэтому и в таблице пусто.

Обход есть, и он полный:

```
meet(f, k)
```

Команда считает пересечение **движком** и кладёт результат в таблицу, не трогая
GeoGebra. Аргументы — буквы объектов с панели (прямая или окружность). Работает
для прямой с прямой, прямой с окружностью и двух окружностей.

Если вдобавок выключить кнопку **«рисовать»** в шапке, чертёж не будет
затрагиваться вовсе — и тогда посчитать можно то, что мышью просто не отметить.


# Бариканатор — второй движок

Всё, что выше, — про Компланатор. Кнопка **«Компланатор» / «Бариканатор»** в
левом верхнем углу переключает движок; таблица при этом пересчитывается заново,
чертёж остаётся на месте.

## Чем он отличается

Компланатор считает в комплексных числах и берёт описанную окружность за
единичную. Это очень экономно ровно до вписанной окружности, биссектрисы и
касания — там всё упирается в корни вида `√(ab)`, и половина задач оказывается
за границей.

Бариканатор считает в барицентрических координатах относительно `ABC`.
Координата точки — однородная тройка `(x : y : z)` через длины сторон `a, b, c`.
В ней:

| | Компланатор | Бариканатор |
|---|---|---|
| инцентр | требует корней | `(a : b : c)` |
| вписанная окружность | требует корней | пишется точно |
| точки касания | требуют корней | рациональны |
| поворот на произвольный угол | легко | только кратный 60° и 90° |
| произвольная точка описанной | одна буква | две |

Правило простое: **если в задаче есть вписанная окружность, биссектриса или
касание — берите Бариканатор. Если всё вращается вокруг описанной — Компланатор.**

## Как читается тройка

`(x : y : z)` — это точка `(xA + yB + zC)/(x + y + z)`. Тройка задана **с
точностью до общего множителя**, поэтому `(1 : 1 : 1)` и `(5 : 5 : 5)` — один и
тот же центроид. Движок множитель снимает и знаменатели убирает сам.

- вершины: `A = (1 : 0 : 0)`, `B = (0 : 1 : 0)`, `C = (0 : 0 : 1)`;
- точка на стороне `BC` — это `(0 : y : z)`, нулевая координата появляется сама;
- сумма координат, равная нулю, — бесконечно удалённая точка; такую движок
  считает, но не рисует, и так и пишет в строке.

**Прямая — тоже тройка**, только читается как уравнение: `(l : m : n)` значит
`lx + my + nz = 0`. Стороны треугольника поэтому выглядят как `(1 : 0 : 0)` и
так далее.

## Три способа записи

Один и тот же ответ можно написать через стороны `a, b, c`, через величины
Конвея (`S_a = (b² + c² − a²)/2`, `S_ω = S_a + S_b + S_c`) и через полупериметр
(`p`, `p−a`, `p−b`, `p−c`). Движок пишет **все три про себя и показывает самую
короткую** — у ортоцентра это Конвей, у точки Жергонна полупериметр.

Кнопка **«кан.»** рядом с точкой, прямой или окружностью разворачивает запись
обратно через стороны `a, b, c` — на случай, когда надо подставить в свою
формулу, а не читать глазами.

## Команды

Всё, что было в Компланаторе, работает и здесь: `collinear`, `perpen`, `paral`,
`angle`, `cocycl`, `similar`, `vectors`, `harm`, `krokhalyator`, построения
`buildpoint`, `buildline`, `radline`, `meet`, `compass`, `tangent`, `conic`,
`homothety`. Разница в трёх местах:

- **`anglesum` убран.** В барицентрике суммы углов считаются через тангенсы и
  раздуваются так, что ответа не дождаться. Это не «забыли», а осознанный отказ.
- **Первообразного корня из единицы нет** — он был нужен комплексному движку.
- **Появились свои:**

```
etc(n)                центр треугольника X(n) из таблицы Кимберлинга
equilateral(X1, X2)   вершины равносторонних треугольников на отрезке X1X2
```

`etc(1)` — инцентр, `etc(4)` — ортоцентр, `etc(13)` — точка Торричелли.
Если центра в таблице нет, движок скажет об этом отдельно — и отдельно же
скажет, если центр в барицентрике **не выражается** в принципе. Это разные
ответы, и путать их не надо.

`equilateral` даёт **две** точки — по одной с каждой стороны отрезка. Обе
осмысленны, поэтому выбирать за вас движок не станет.

## Строка выражений

Своя, барицентрическая:

```
line(X1, X2)      прямая через две точки
det(X1, X2, X3)   определитель — ноль ровно тогда, когда точки на одной прямой
X1 - X2           вектор из X2 в X1 (ненормированный)
abs(X1 - X2)      КВАДРАТ длины (не длина: длина иррациональна)
O1 - O2           радикальная ось двух окружностей; точка = окружность нулевого радиуса
EFFT(v1, v2)      a²(y₁z₂+z₁y₂) + b²(z₁x₂+x₁z₂) + c²(x₁y₂+y₁x₂)
```

Есть ещё `centre(k)`, `polar(k, P)`, `pow(k, P)` — центр, поляра и степень
точки относительно окружности.

Кнопка **«без дробей»** домножает ответ на общий знаменатель. Насовсем убирать
дроби нельзя: у вектора это потеряло бы масштаб, а с ним и длину.

## Про повороты и √3

Барицентрика поворотов не знает: у неё есть длины и площади, но нет углов.
Поворот упирается в площадь `S`, а она иррациональна — её нельзя выписать
многочленом от `a, b, c` (многочленом выписывается только `S²`).

Движок присоединяет её **одним корнем**. Для углов, кратных 60°, это ровно
`√3·S`, для кратных 90° — сама `S`. Дальше всё считается точно, и в записи
появляется множитель `√3 S` — это не приближение, это точная величина.

Поэтому работают:

- команда `equilateral`;
- точки Торричелли `etc(13)`, `etc(14)`;
- изодинамические (аполлониевы) `etc(15)`, `etc(16)`;
- точки Наполеона `etc(17)`, `etc(18)`;
- команда GeoGebra **«Повернуть»** на угол, кратный 60° или 90° — движок её
  разберёт и построенную точку возьмёт в таблицу.

30° и 45° потребовали бы **двух** корней сразу — про них движок скажет прямо,
что это пока не сделано. Это не то же самое, что «не знаю».

Одна тонкость с ориентацией: площадь берётся **со знаком**, и от него зависит,
куда смотрит «наружу». Поэтому если перетащить вершину так, чтобы обход `A→B→C`
сменил направление, точки Ферма поменяются местами — и это правильно, а не сбой.

## Пример: точка Торричелли

```
etc(T = 13)
```

Всё. Точка появится на чертеже, а в таблице — её координата

```
(−2(S_aS_b + S_aS_c + 4S_bS_c) − 2a²·√3S : … : …)
```

Хотите проверить, что это она? Постройте отрезки `TA`, `TB`, `TC` и померьте
углы — все три по 120°.

## Пример: равносторонний треугольник наружу

```
equilateral(P = B, C)
```

Появятся две точки: `P` и `K1` — по одной с каждой стороны от отрезка `BC`.
Выберите нужную и стройте дальше.

Чевианы к трём таким вершинам (по одной на каждой стороне) сходятся в точке
Ферма. Это проверяется прямо в движке: постройте вершины на всех трёх сторонах,
возьмите `etc(T = 13)` и напишите в строке условий `collinear(A, P, T)` — она
скажет «выполняется всегда».

## Чего Бариканатор не умеет

- углы, не кратные 60° и 90°;
- `anglesum` (убран нарочно, см. выше);
- центры `X(61)`, `X(62)` и подобные — они требуют `√3` в сочетании, которого
  движок пока не строит;
- двух неизвестных точек сразу в одной системе — как и в Компланаторе, стройте
  по очереди.
